# Internationalization (i18n) Plan for PPTist

## Goal
Add support for 3 languages (Chinese, English, Russian) to the PPTist Vue 3 presentation editor application.

## Approach

### 1. Install vue-i18n
- Install `vue-i18n@9` (latest available; v11 exists but v9 is stable and well-documented)
- No other new dependencies needed

### 2. Create i18n Infrastructure
```
src/i18n/
  index.ts              - Plugin setup, createI18n instance, compositional helpers
  locale/
    zh.ts               - Chinese translations (current hardcoded strings)
    en.ts               - English translations
    ru.ts               - Russian translations
```

- `src/i18n/index.ts`: Use `createI18n({ legacy: false, locale: derived from localStorage then navigator.language, fallbackLocale: 'en', messages: { zh, en, ru } })`
- Support language persistence via localStorage (key: `PPTIST_LOCALE`)
- Store language preference in the existing store configuration

### 3. Add Locale Storage Key
- `src/configs/storage.ts`: Add `export const LOCALSTORAGE_KEY_LOCALE = 'PPTIST_LOCALE'`

### 4. Register i18n in main.ts
- Import i18n from `@/i18n`
- Add `app.use(i18n)` before `app.mount('#app')`
- Extend `global.d.ts` with vue-i18n type declarations

### 5. Create Language Switcher Component
- New component: `src/components/LanguageSwitcher.vue`
- Dropdown/select component with 3 options: 中文 / English / Русский
- Icon-based (globe/language icon) with text label for expanded view
- Uses the existing `Select` or `Popover` infrastructure from the codebase
- Emits/stores language change via `i18n.global.locale.value = ...`

### 6. Integrate into EditorHeader
- Add `LanguageSwitcher` in `src/views/Editor/EditorHeader/index.vue` in the `.right` section
- Place it after the GitHub link icon for visibility without cluttering the toolbar
- Style: compact button/dropdown matching existing header style

#### Vue Files (~85 files)
All files containing Chinese text in:
- Template strings (v-tooltip attributes, button labels, labels, placeholders, titles)

### 9. Refactoring Pattern

In `.vue` files:
```vue
<!-- Before -->
<span>{{ '输入一句话，智能生成演示文稿' }}</span>
<div v-tooltip="'幻灯片放映（F5）'">...</div>
<button>导出</button>

<!-- After -->
<span>{{ t('header.aippt.subtitle') }}</span>
<div v-tooltip="t('header.slideshow')">...</div>
<button>{{ t('export.button') }}</button>
```

In `<script>` sections:
```typescript
// Before
message.error('未知的请求错误！')

// After
const { t } = useI18n()
message.error(t('message.unknownError'))
```

Config files with labels:
```typescript
// Before
export const ELEMENT_TYPE_ZH = { text: '文本', image: '图片', ... }

// After
// Remove from element.ts entirely
// Access via: t(`elementType.${type}`) from i18n locale files
```

### 10. Fallback Strategy
- Default locale: Chinese (current user base) if browser is zh-CN, otherwise English
- All 3 locales must have complete coverage
- Missing keys fall back to English, then to the key itself as string
- `warnHtmlMessage: false` for safety (app has no user HTML in translations)

### 11. What NOT to Translate
- User-generated content: slide text, notes content, chart data values, image titles
- File URLs, API endpoints, URLs
- Code variable names, technical identifiers
- The word "AIPPT" (product name), "PPTX", "JSON", "PPTIST"

### 12. Testing Approach
- Manual testing: switch between CN/EN/RU, verify all UI elements render correctly
- Check that dynamic messages (error/warning) appear in correct language
- Verify context menus translate correctly
- Ensure RTL doesn't interfere (not needed for these languages, but check LTR is maintained)
- Test language persistence: page reload should remember selection

### 15. Potential Challenges & Solutions
- **Large config files**: Animation names (~70 entries), hotkey descriptions (~60 entries) - these should go into locale files as structured objects, not flat strings
- **Dynamic text**: Template literals like `幻灯片X的批注` - convert to `t('notes.title', { slideIndex: n + 1 })` with named interpolation
- **v-tooltip**: These are attributes, not content slots - Vue's `v-tooltip` directive accepts reactive values, `t()` returns a string that works fine
- **Context menus**: Built dynamically in JS - replace string literals with `t()` calls
- **Performance**: 400+ locale keys is negligible for vue-i18n's performance
